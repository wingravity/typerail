# TR402: Overridden method called from a base constructor

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | Not checked yet |
| Priority | P2: request fails |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
class Base {
  constructor() {
    this.init();
  }

  init(): void {}
}

class Counter extends Base {
  step = 1;

  override init(): void {
    this.step.toFixed();
  }
}

export function proof(): Counter {
  return new Counter();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toFixed')`

The example is [`test/gaps/TR402.ts`](../../test/gaps/TR402.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A base class constructor runs before the subclass's field initializers. When it calls a method that the subclass overrides, the override runs while the subclass's fields are still undefined, although their types say otherwise.

## How typerail detects it

Not checked yet. A rule needs to follow calls from constructors through overridable methods. This code documents the gap.

## How to fix it

Do not call overridable methods from a constructor. Initialize in the subclass constructor, or create the object with a factory function that calls `init` after construction.
