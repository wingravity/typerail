# TR204: Non-null assertion

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-non-null-assertion` |
| Priority | P2: request fails |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
const settings = new Map<string, string>();

export function proof(): string {
  const theme = settings.get("theme")!;
  return theme.toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR204.ts`](../../test/gaps/TR204.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

The postfix `!` removes `null` and `undefined` from a type without a runtime check.

## How typerail detects it

`@typescript-eslint/no-non-null-assertion` reports every non-null assertion.

## How to fix it

Check the value (`if (theme === undefined) return ...`) or provide a default (`?? "light"`).
