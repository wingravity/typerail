# TR306: Class merged with an interface

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-unsafe-declaration-merging` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
interface Label {
  text: string;
}

class Label {}

export function proof(): string {
  return new Label().text.toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR306.ts`](../../test/gaps/TR306.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

An interface and a class with the same name merge into one declaration. The class then appears to have the interface's members, although the class never initializes them.

## How typerail detects it

`@typescript-eslint/no-unsafe-declaration-merging` reports a class and an interface that merge.

## How to fix it

Rename one of them, or declare and initialize the members in the class.
