# TR208: Type argument used only for the return type

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `typerail/no-return-type-argument` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface User {
  name: string;
}

function parseAs<T>(text: string): T {
  return JSON.parse(text);
}

export function proof(): string {
  const user = parseAs<User>('{"id":1}');
  return user.name.toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR208.ts`](../../test/gaps/TR208.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

When a type parameter appears only in the return type, nothing in the call constrains it, so the caller's type argument is an unchecked claim about the result. `parseAs<User>(text)`, `get<User>(url)` and `document.querySelector<HTMLButtonElement>("#save")` all work this way. They read like typed APIs and behave like `as`.

## How typerail detects it

`typerail/no-return-type-argument` reports an explicit type argument whose type parameter does not appear in any parameter of the called function and does appear in its return type as a value. These are not reported, because they claim nothing about existing data:

- Return types that only hold the type in a collection, such as `empty<T>(): T[]` or `new Map<K, V>()`.
- Calls without arguments that create empty state, where the type appears only as `T | undefined`, such as `createSignal<T>()` or `useState<T>()`.
- Branded primitives, such as Drizzle's `integer().$type<UserId>()` with `type UserId = number & { __brand: "UserId" }`. The brand exists only at compile time, and the column type already guarantees the primitive.

Type arguments inferred from the expected type of the result are not checked yet.

## How to fix it

Leave the type argument out, keep the result as `unknown` or the declared base type, and validate it. For DOM lookups, check with `instanceof HTMLButtonElement`.
