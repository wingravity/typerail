# TR201: Type assertion

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/consistent-type-assertions` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
interface User {
  name: string;
}

export function proof(): string {
  const raw: unknown = { id: 1 };
  const user = raw as User;
  return user.name.toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR201.ts`](../../test/gaps/TR201.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A type assertion tells the compiler which type to use and is removed from the emitted JavaScript. TypeScript checks only that the two types overlap, and `as unknown as T` removes even that check.

## How typerail detects it

`@typescript-eslint/consistent-type-assertions` with `assertionStyle: "never"` reports every assertion except `as const`.

## How to fix it

Narrow the value with checks (`typeof`, `in`, `Array.isArray`, `instanceof`), or validate it with a schema library and use its result.
