# TR401: Narrowing kept after a call

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | Not checked yet |
| Priority | P2: request fails |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface State {
  value: string | number;
}

function reset(state: State): void {
  state.value = 0;
}

export function proof(): string {
  const state: State = { value: "ready" };
  if (typeof state.value === "string") {
    reset(state);
    return state.value.toUpperCase();
  }
  return "";
}
```

At runtime: `TypeError: state.value.toUpperCase is not a function`

The example is [`test/gaps/TR401.ts`](../../test/gaps/TR401.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

TypeScript keeps the narrowed type of a property across function calls. Invalidating every narrowing at every call would make most narrowing useless, so the compiler assumes calls do not change the narrowed property.

## How typerail detects it

Not checked yet. A rule needs to know which calls can change the object, and a simple rule would report a lot of correct code. This code documents the gap.

## How to fix it

Copy the narrowed value into a local constant before the call (`const value = state.value`) and use the constant afterwards.
