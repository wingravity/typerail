# TR205: Definite assignment assertion

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `typerail/no-definite-assignment` |
| Priority | P2: request fails |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface Client {
  send(): string;
}

class Service {
  client!: Client;

  run(): string {
    return this.client.send();
  }
}

export function proof(): string {
  return new Service().run();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'send')`

The example is [`test/gaps/TR205.ts`](../../test/gaps/TR205.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A definite assignment assertion (`client!: Client` or `let value!: number`) turns off the check that a field or variable is assigned before it is read. It exists for fields initialized by frameworks or helper methods that the compiler cannot follow.

## How typerail detects it

`typerail/no-definite-assignment` reports definite assignment assertions on class fields and variables.

## How to fix it

Initialize the field in its declaration or constructor, or type it as `Client | undefined` and check it before use.
