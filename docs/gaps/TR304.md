# TR304: Copy that drops the prototype

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-misused-spread`, `typerail/no-structured-clone-instance` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
class Session {
  constructor(readonly user: string) {}

  greeting(): string {
    return `Hello, ${this.user}`;
  }
}

export function proof(): string {
  const copy = structuredClone(new Session("ada"));
  return copy.greeting();
}
```

At runtime: `TypeError: copy.greeting is not a function`

The example is [`test/gaps/TR304.ts`](../../test/gaps/TR304.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

Object spread copies own enumerable properties, and `structuredClone` copies data, but neither keeps the prototype. TypeScript types `{ ...instance }` as having the class's methods in some cases, and types `structuredClone<T>(value: T): T` as returning the same class.

## How typerail detects it

`@typescript-eslint/no-misused-spread` reports spreading a class instance, and `typerail/no-structured-clone-instance` reports `structuredClone` on an instance of a project class that has methods or accessors. Built-in types that `structuredClone` supports, such as `Date` and `Map`, are allowed.

## How to fix it

Give the class a `clone()` method or copy it through its constructor. Spread and clone plain data objects only.
