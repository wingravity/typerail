# TR604: Caught value treated as an Error

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `useUnknownInCatchVariables` in `@wingravity/typerail/tsconfig.json` |
| Priority | P2: request fails |

## Example

TypeScript accepts this code when `useUnknownInCatchVariables` is off:

```ts
export function proof(): number {
  try {
    throw "connection lost";
  } catch (error) {
    return error.message.length;
  }
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'length')`

The example is [`test/gaps/TR604.ts`](../../test/gaps/TR604.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

JavaScript can throw any value, not only `Error` objects. Without `useUnknownInCatchVariables`, the variable in `catch (error)` is `any`, so `error.message` compiles.

## How typerail detects it

`typerail check` compiles with `useUnknownInCatchVariables` (part of `strict`, and set explicitly). The flag is on for typerail even when the project's tsconfig turns it off.

## How to fix it

Enable the flag and narrow caught values (`error instanceof Error ? error.message : String(error)`).
