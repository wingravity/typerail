# TR607: Import with the wrong letter case

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `forceConsistentCasingInFileNames` in `@wingravity/typerail/tsconfig.json` |
| Priority | P0: process can go down |

## Example

TypeScript accepts this code when `forceConsistentCasingInFileNames` is off:

```ts
import { greeting } from "./TR607-Target.js";

export function proof(): string {
  return greeting;
}
```

The example is [`test/gaps/TR607.ts`](../../test/gaps/TR607.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

macOS and Windows file systems ignore letter case by default, so `import "./TR607-Target.js"` finds `TR607-target.ts` there. Linux file systems do not, so the same import fails in a Linux container or CI. The example compiles on macOS without the flag and cannot run on Linux.

## How typerail detects it

`typerail check` compiles with `forceConsistentCasingInFileNames`, which reports imports whose case differs from the file name. The flag is on for typerail even when the project's tsconfig turns it off.

## How to fix it

Enable the flag and match the file name exactly.
