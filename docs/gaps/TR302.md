# TR302: Plain object used as a class instance

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-unsafe-class-instance-assignment` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
class Session {
  constructor(readonly user: string) {}
}

function describe(value: Session | string): string {
  if (value instanceof Session) {
    return value.user;
  }
  return value.toUpperCase();
}

export function proof(): string {
  const session: Session = { user: "ada" };
  return describe(session);
}
```

At runtime: `TypeError: value.toUpperCase is not a function`

The example is [`test/gaps/TR302.ts`](../../test/gaps/TR302.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

TypeScript compares classes structurally. A plain object with the same public members is accepted as a class instance, but it is not created by the class, so `instanceof` returns false. Code that narrows with `instanceof` then treats the object as another member of the union.

## How typerail detects it

`@typescript-eslint/no-unsafe-class-instance-assignment` reports a non-instance value assigned to a class instance type. The rule exists in typescript-eslint 8.73 and later; typerail enables it when the installed version has it.

## How to fix it

Create the value with `new`, or type the location as an interface instead of the class. Give the class a private field when structural matches must be impossible.
