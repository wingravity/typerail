# TR104: Tuple changed by an array method

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `typerail/no-tuple-mutation` |
| Priority | P2: request fails |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
export function proof(): string {
  const point: [number, number] = [1, 2];
  point.pop();
  return point[1].toFixed();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toFixed')`

The example is [`test/gaps/TR104.ts`](../../test/gaps/TR104.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A mutable tuple type is an array with fixed positions, and it inherits every array method. `push`, `pop`, `shift`, `unshift` and `splice` change its length, and `reverse`, `sort`, `fill` and `copyWithin` move elements between positions, while the type keeps describing the original layout.

## How typerail detects it

`typerail/no-tuple-mutation` reports length-changing methods and `length` assignments on mutable tuples, and order-changing methods on tuples whose elements have different types.

## How to fix it

Build a new tuple instead (`[first, second]`), or type the value as a readonly tuple or an array.
