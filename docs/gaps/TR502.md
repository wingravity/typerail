# TR502: Promise where a void result is expected

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-misused-promises` |
| Priority | P0: process can go down |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
async function save(id: number): Promise<void> {
  await Promise.resolve();
  throw new Error(`save ${String(id)} failed`);
}

export function proof(): void {
  [1, 2].forEach(async (id) => {
    await save(id);
  });
}
```

At runtime: `Error: save 1 failed, reported as an unhandled rejection. Node stops the process.`

The example is [`test/gaps/TR502.ts`](../../test/gaps/TR502.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A function that returns a value is accepted where a callback returning `void` is expected, so an async function can be passed to `forEach`, event emitters and other APIs that ignore the returned promise. Its rejection is never handled.

## How typerail detects it

`@typescript-eslint/no-misused-promises` reports async functions and promises passed where the result is ignored or a boolean is expected. JSX attributes such as `onClick={async () => ...}` are not reported: event handlers run only in the browser, where an unhandled rejection is logged and does not stop anything. Handle errors inside such handlers all the same.

## How to fix it

Use `for...of` with `await`, or `Promise.all(items.map(...))`, or handle the rejection inside the callback.
