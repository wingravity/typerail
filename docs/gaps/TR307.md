# TR307: const enum inlined from another package

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | Not checked yet |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
import { Mode, run } from "./TR307-lib.js";

export function proof(): string {
  return run(Mode.Fast);
}
```

At runtime: `TypeError: handlers[mode] is not a function`

The example is [`test/gaps/TR307.ts`](../../test/gaps/TR307.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

References to an ambient `const enum` are replaced with the member's value at compile time. When the package that declares the enum is upgraded and its values change, compiled code keeps the old numbers. The example compiles against `Mode.Fast = 1` from `TR307-lib.d.ts`, while `TR307-lib.js`, the newer runtime, expects 2.

## How typerail detects it

Not checked yet. `isolatedModules` reports references to ambient const enums, but it also changes how other code must be written, so typerail does not enable it. This code documents the gap.

## How to fix it

Do not publish or consume `const enum` across package boundaries. Use a regular enum or a union of literals.
