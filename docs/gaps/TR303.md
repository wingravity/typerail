# TR303: Number used as a numeric enum

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-unsafe-enum-assignment` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
enum Status {
  Pending,
  Complete,
}

function label(status: Status): string {
  switch (status) {
    case Status.Pending:
      return "pending";
    case Status.Complete:
      return "complete";
  }
}

export function proof(): string {
  const raw: number = 7;
  const status: Status = raw;
  return label(status).toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR303.ts`](../../test/gaps/TR303.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

Any `number` is assignable to a numeric enum type. TypeScript 5.0 rejects numeric literals that are not members, but a value of type `number`, such as one read from a database or a request, is still accepted. A `switch` over the members then matches nothing.

## How typerail detects it

`@typescript-eslint/no-unsafe-enum-assignment` reports a non-enum value assigned to an enum type. The rule exists in typescript-eslint 8.71 and later; typerail enables it when the installed version has it.

## How to fix it

Check the number against the enum's members before converting it, or use a union of string literals for closed sets.
