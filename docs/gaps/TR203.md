# TR203: Compiler directive comment

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/ban-ts-comment` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
export function proof(): string {
  const count: number = 1;
  // @ts-expect-error the value is a number at runtime
  const label: string = count;
  return label.toUpperCase();
}
```

At runtime: `TypeError: label.toUpperCase is not a function`

The example is [`test/gaps/TR203.ts`](../../test/gaps/TR203.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

`@ts-ignore`, `@ts-expect-error` and `@ts-nocheck` suppress compiler errors on a line or a whole file. The code still runs exactly as written.

## How typerail detects it

`@typescript-eslint/ban-ts-comment` reports the three directives. `@ts-check` is allowed.

## How to fix it

Fix the error that the comment hides.
