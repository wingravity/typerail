# TR305: Deleted array element

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-array-delete` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
export function proof(): string[] {
  const names = ["ada", "grace"];
  delete names[0];
  const upper: string[] = [];
  for (const name of names) {
    upper.push(name.toUpperCase());
  }
  return upper;
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR305.ts`](../../test/gaps/TR305.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

`delete items[0]` removes the element and leaves a hole. The array keeps its length, `for...of` yields `undefined` for the hole, and the element type does not include `undefined`.

## How typerail detects it

`@typescript-eslint/no-array-delete` reports `delete` on array elements.

## How to fix it

Use `splice` to remove the element in place, or `filter` to build a new array.
