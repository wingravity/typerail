# TR202: Explicit any

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-explicit-any` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
function load(): any {
  return { count: "many" };
}

export function proof(): string {
  const total: number = load().count;
  return total.toFixed();
}
```

At runtime: `TypeError: total.toFixed is not a function`

The example is [`test/gaps/TR202.ts`](../../test/gaps/TR202.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

`any` disables type checking for the value and for every expression it flows into. `strict` reports implicit `any`, but an explicit `any` is accepted everywhere.

## How typerail detects it

`@typescript-eslint/no-explicit-any` reports `any` written in a type.

## How to fix it

Use `unknown` and narrow it, or write the real type. See TR301 for `any` that comes from APIs.
