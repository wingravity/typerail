# TR101: Mutable array covariance

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `typerail/no-mutable-array-widening` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): string;
}

const rex: Dog = { name: "Rex", bark: () => "woof" };

export function proof(): string {
  const dogs: Dog[] = [rex];
  const animals: Animal[] = dogs;
  animals.push({ name: "Tom" });
  const dog = dogs[1];
  return dog === undefined ? "" : dog.bark();
}
```

At runtime: `TypeError: dog.bark is not a function`

The example is [`test/gaps/TR101.ts`](../../test/gaps/TR101.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

Arrays are covariant in TypeScript: a `Dog[]` is assignable to an `Animal[]`. Covariance is sound for reading and unsound for writing, and TypeScript does not distinguish the two for arrays. The choice keeps common code such as passing a `string[]` to a function that takes `unknown[]` working.

## How typerail detects it

`typerail/no-mutable-array-widening` reports an existing mutable array that is assigned, passed, returned or stored where a mutable array of a wider element type is expected. Fresh arrays, copies and readonly targets are allowed. Arrays passed to functions declared in `node_modules` and targets whose element type is `unknown` or `any` are not reported, because such code reads the array and does not write to it. Differences only in branded types, such as `Seconds` declared as `number & { __brand: "Seconds" }` against `number`, are not reported either: brands exist only at compile time, so the runtime values are the same.

## How to fix it

Type the target as `readonly Animal[]` when it only reads. Pass a copy (`[...dogs]`) when the callee needs a mutable array of the wider type.
