# TR602: Unchecked index access

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `noUncheckedIndexedAccess` in `@wingravity/typerail/tsconfig.json` |
| Priority | P2: request fails |

## Example

TypeScript accepts this code when `noUncheckedIndexedAccess` is off:

```ts
const names: string[] = [];

export function proof(): string {
  return names[0].toUpperCase();
}
```

At runtime: `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`

The example is [`test/gaps/TR602.ts`](../../test/gaps/TR602.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

`strict` does not include `noUncheckedIndexedAccess`. Without it, reading `items[0]` or `record[key]` is typed as the element type even when nothing is there.

## How typerail detects it

`typerail check` compiles with `noUncheckedIndexedAccess`, which adds `undefined` to indexed reads. The flag is on for typerail even when the project's tsconfig turns it off.

## How to fix it

Enable the flag and check indexed values (`const first = items[0]; if (first === undefined) return ...`).
