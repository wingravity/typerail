# TR102: Mutable property covariance

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `typerail/no-mutable-property-widening` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): string;
}

const rex: Dog = { name: "Rex", bark: () => "woof" };

interface Box<T> {
  value: T;
}

export function proof(): string {
  const dogBox: Box<Dog> = { value: rex };
  const animalBox: Box<Animal> = dogBox;
  animalBox.value = { name: "Tom" };
  return dogBox.value.bark();
}
```

At runtime: `TypeError: dogBox.value.bark is not a function`

The example is [`test/gaps/TR102.ts`](../../test/gaps/TR102.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

Object properties are covariant in TypeScript, including writable ones. `Box<Dog>` is assignable to `Box<Animal>` because `Dog` is assignable to `Animal`, although writing an `Animal` through the second reference breaks the first. The same hole lets a discriminated union be rewritten through a wider alias (`{ kind: "ok" }` stored as `{ kind: "ok" | "error" }`), and an object be stored into a writable `Record<string, Animal>`. TypeScript infers the variance of a generic type from its members and does not treat writable properties as invariant.

## How typerail detects it

`typerail/no-mutable-property-widening` reports an existing object that is assigned, passed, returned or stored where one of its properties becomes writable with a wider type, up to three levels deep, including writable index signatures. Readonly target properties, copies and fresh object literals are allowed. Objects passed to functions declared in `node_modules`, target types declared there, and target properties typed `unknown`, `any`, `object` or `{}` are not checked, because their declarations cannot be changed or they only read what they receive. Function-typed properties are not checked, because TypeScript already checks function parameters strictly, and neither are differences only in branded types, which exist only at compile time.

## How to fix it

Mark the target's properties `readonly`, or accept `Readonly<Box<Animal>>`. Pass a copy (`{ ...box }`) when the callee must write. For a generic type whose parameter is both read and written, declare it invariant with a variance annotation (TypeScript 4.7 and later), and the compiler rejects the widening itself:

```ts
interface Box<in out T> {
  value: T;
}
```
