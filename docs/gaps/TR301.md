# TR301: any from an API

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/no-unsafe-assignment`, `@typescript-eslint/no-unsafe-member-access`, `@typescript-eslint/no-unsafe-call`, `@typescript-eslint/no-unsafe-argument`, `@typescript-eslint/no-unsafe-return` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `@wingravity/typerail/tsconfig.json`:

```ts
interface Account {
  balance: number;
}

export function proof(): string {
  const account: Account = JSON.parse('{"balance":"unlimited"}');
  return account.balance.toFixed();
}
```

At runtime: `TypeError: account.balance.toFixed is not a function`

The example is [`test/gaps/TR301.ts`](../../test/gaps/TR301.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

The standard library types `JSON.parse` and `Response.json()` as returning `any`, and many libraries do the same. An `any` from an API is accepted by every typed location, so `const account: Account = JSON.parse(text)` compiles without a cast. The rejection reason in `.catch((error) => ...)` is `any` as well.

## How typerail detects it

The `no-unsafe-*` rules of typescript-eslint (`no-unsafe-assignment`, `no-unsafe-member-access`, `no-unsafe-call`, `no-unsafe-argument`, `no-unsafe-return`) report where an `any` reaches a typed location or is used.

## How to fix it

Assign the value to `unknown` (`const data: unknown = JSON.parse(text)`), then narrow or validate it.
