# TR605: Switch case fallthrough

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `noFallthroughCasesInSwitch` in `@wingravity/typerail/tsconfig.json` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code when `noFallthroughCasesInSwitch` is off:

```ts
function price(tier: "free" | "pro"): number {
  let total = 0;
  switch (tier) {
    case "free":
      total += 0;
    case "pro":
      total += 20;
      break;
  }
  return total;
}

export function proof(): { expected: number; actual: number } {
  return { expected: 0, actual: price("free") };
}
```

At runtime: The function returns 20 for the free tier.

The example is [`test/gaps/TR605.ts`](../../test/gaps/TR605.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A `case` that does not end with `break`, `return` or `throw` runs into the next one. This is valid JavaScript, so TypeScript accepts it unless `noFallthroughCasesInSwitch` is on.

## How typerail detects it

`@wingravity/typerail/tsconfig.json` enables `noFallthroughCasesInSwitch`. `typerail report` lists a project that turns it off.

## How to fix it

Enable the flag and end every non-empty case.
