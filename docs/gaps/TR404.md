# TR404: Switch that misses a union member

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `@typescript-eslint/switch-exhaustiveness-check` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code under `typerail/tsconfig.json`:

```ts
type Shape = { kind: "circle"; radius: number } | { kind: "square"; side: number };

function describe(shape: Shape): string {
  let text = "unknown shape";
  switch (shape.kind) {
    case "circle":
      text = `circle of radius ${String(shape.radius)}`;
      break;
  }
  return text;
}

export function proof(): { expected: string; actual: string } {
  return { expected: "square of side 2", actual: describe({ kind: "square", side: 2 }) };
}
```

At runtime: The function returns `"unknown shape"` for a square.

The example is [`test/gaps/TR404.ts`](../../test/gaps/TR404.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

A `switch` does not have to handle every member of a union. When a member is missing, or is added later, execution continues after the switch with whatever the code there assumes. The types are accurate; the result is silently wrong.

## How typerail detects it

`@typescript-eslint/switch-exhaustiveness-check` reports a `switch` over a union that misses a member. A `default` case does not count as handling the members.

## How to fix it

Add a case for every member of the union, and let the compiler report new members.
