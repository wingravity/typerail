# TR002: Inline eslint-disable comment

| | |
|---|---|
| Kind | A typerail finding, not a gap in TypeScript |
| Checked by | typerail |
| Priority | P4: no runtime effect |

## What it means

This is not a gap in TypeScript. It applies only to projects that use typerail's optional ESLint preset for editor integration. The preset sets `noInlineConfig`, so `// eslint-disable` comments do nothing. Coding agents often add them to make a check pass, so the comment is reported to make the attempt visible. `typerail check` runs its own ESLint instance and ignores these comments without reporting them.

## How typerail detects it

With the ESLint preset, ESLint reports the inert comment in the editor and in `eslint` runs.

## How to fix it

Remove the comment and fix the finding. `typerail check` reports the finding whatever the comment says. `allowInlineDisable: true` turns inline comments back on for the preset, but not for `typerail check`.
