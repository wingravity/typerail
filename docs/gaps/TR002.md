# TR002: Inline eslint-disable comment

| | |
|---|---|
| Kind | A typerail finding, not a gap in TypeScript |
| Checked by | typerail |
| Priority | P4: no runtime effect |

## What it means

This is not a gap in TypeScript. typerail sets `noInlineConfig`, so `// eslint-disable` comments do nothing. Coding agents often add them to make a check pass, so the comment is reported to make the attempt visible.

## How typerail detects it

ESLint reports the inert comment, and `typerail report` lists it.

## How to fix it

Remove the comment. If an exception is deliberate, add it to `eslint.config.js`, where it is visible in review and listed in the report's configuration section. `allowInlineDisable: true` turns inline comments back on.
