# TR601: strict is off

| | |
|---|---|
| Status | Open in TypeScript 6.0.3 |
| Checked by | `strict` in `typerail/tsconfig.json` |
| Priority | P1: silent wrong result |

## Example

TypeScript accepts this code when `strict` is off:

```ts
function length(text: string): number {
  return text.length;
}

export function proof(): number {
  return length(null);
}
```

At runtime: `TypeError: Cannot read properties of null (reading 'length')`

The example is [`test/gaps/TR601.ts`](../../test/gaps/TR601.ts). The test suite checks that TypeScript still accepts it and that it still fails when run.

## Why TypeScript allows it

With `strict` off, `null` and `undefined` are accepted by every type, function parameters are checked bivariantly, and implicit `any` is allowed.

## How typerail detects it

`typerail/tsconfig.json` enables `strict`. `typerail report` lists a project that turns it off.

## How to fix it

Enable `strict` and fix the errors it reports.
